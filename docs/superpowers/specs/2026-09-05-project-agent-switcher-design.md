# 作業セット・エージェントランチャー・引き継ぎの設計

日付: 2026-09-05。ユーザーとの会話で合意した方向性を実装可能な範囲に具体化した設計。
本書と実装計画は提案仕様。機能の実装・CLI実機互換性確認はまだ行っていない。

## 目的

プロジェクトを選び、Claude / Codex / Antigravityを使い分け、作業の続きへ戻る。
最優先は所有者の復帰作業の短縮。OSSとしての成長はその結果として狙う。
成功指標は復帰の操作数、復元成功率、エージェント切り替え時の説明の手間。

## 共通制約

- Python >= 3.11。新しいランタイム依存パッケージを追加しない。
- 既存の `saikai` 起動、Claude履歴一覧、split-live、前回ペイン復元を維持する。
- provider-specificなコマンド構築は `saikai_provider.py` に置く。
- `saikai_terminal.py` にエージェント固有の起動・履歴仕様を追加しない。
- 保存済み作業セットは自動更新しない。明示的な保存・更新時だけ変更する。
- プロバイダーの非公開履歴形式・内部DB・TUI画面文字列に、新機能を依存させない。
- コマンドは引数配列とcwdで実行し、`shell=True` や文字列置換のシェルコマンドを使わない。
- 認証情報・トークン・環境変数全体を作業セットや引き継ぎに保存しない。
- UIスレッドでCLI照会、Git照会、ファイルロック待ち、子プロセス待機をしない。
- SSH通信・常駐サーバー・遠隔操作プロトコルは実装しない。
- 実行対象はsaikai自身が動いているホスト。同じ機械の別ユーザーも別の保存領域として扱う。
- 他ホストの登録をローカルで実行しない。移植にはユーザーによる明示的な再登録が必要。

## 既存コードとの重要な接点

`saikai.py` の `_ACTIVE_PROVIDER` はClaude固定で、履歴ルート、パース、ライブ状態などが
それを前提にしている。単にこの変数を切り替えて3製品を対応済みにしない。
CodexProviderは起動契約だけ実装済み。新しいランチャー用の公開コマンド構築を
既存AgentProviderの履歴・ライブ状態契約と分けて追加する。

`action_resume_detached` は既存ペインをkillしてから `_resume_claude` に進む。
新ランチャーに流用するとRemote Control中のClaudeを止めるため、流用しない。
新入口 `saikai --launcher` は専用の小さなApp。PTYペインやミラーを所有せず、
Appを終了して端末を返してから公式CLIを前景で実行し、その終了後に一覧へ戻る。
既存のClaude監督画面と同時に使いたい場合は、別の端末でこの入口を開く。

## 段階A: 名前付き作業セット

作業セットは「ホスト・プロジェクトcwd・provider・再開方法」の順序付きスナップショット。
同じプロジェクトの複数のClaude会話を含められる。例: 「個人開発」「調査の続き」。
UUIDを内部ID、名前を表示名として分離し、名前をファイルパスに使わない。

初版は既存のClaudeペインを保存・復元できる。保存は登録済みの生存ペインだけを対象にし、
起動受付中のペインがあれば「起動完了後に保存」を案内する。空集合で既存セットを上書きしない。
閉じたペイン、後日の起動・終了、復元の一部失敗で保存セットが削られることはない。
以前の `open-panes.json` は明示的な「前回のペインから保存」で取り込み、元ファイルを維持する。

保存先は `platformdirs.user_data_dir("saikai")/workspaces.json`。
cache掃除で消えない場所にする。schema_versionとrevisionを持つJSONとし、
OSのファイルロック＋同一ディレクトリの一時ファイル＋os.replaceで更新する。
ロックはPOSIX fcntl / Windows msvcrtを利用。ロック待ち最大2秒。
編集開始時のrevisionが変わっていたら上書きせず、再読込を案内する。
壊れたJSON、未知のスキーマ版を空データとして保存し直さない。

復元前に対象一覧を示し、欠落cwd・他ホスト・重複・現在開いている会話・容量制限を表示する。
既存の別ウィンドウ起動確認とRAMゲートを維持する。受付・確認待ち・スキップを区別する。
名前付きセットの復元は既存の「前回ペインを復元」と別の操作にする。

## 段階B: プロジェクト別ランチャー

プロジェクト一覧 → provider選択 → 新規 / 再開 → 起動。
プロジェクトごとに最後に選んだproviderと再開指定を覚える。
再開指定は `new` / `id` / `picker` / `continue` を区別する。
「最新の会話」と「このIDの会話」は違うものとして表示・保存する。

Claude/CodexのIDは公式に利用できる指定だけ保存する。Codexの新規セッションIDを
非公開ログ解析で自動取得しない。未取得なら「ID未登録」と表示し、公式pickerまたはcontinueを
使用する。ユーザーによるID登録を用意する。Antigravityはまず `agy` と `agy --continue`、
起動後の公式 `/resume` 案内までを扱う。ID指定は実機と公式文書の双方で確認できる場合だけ対応する。
実行ファイル名は通常PATHから解決し、ユーザー設定で実行ファイルの絶対パスを指定できる。
任意のシェルテンプレート、暗黙の権限モード変更は入れない。

既存TUIを表示したまま別providerを埋め込み起動する機能は初版に含めない。
既存プロセスの強制終了や操作中CLIへの割り込みを「切り替え」として実装しない。
元CLIから通常終了して一覧へ戻り、次を開く。終了済みであっても会話履歴は公式機能で再開する。
CLIの終了コード0を「作業完了」や「遠隔接続成功」と解釈しない。

混在セットは一覧から項目を選んで開く。Claudeだけのセットは段階Aで一括復元できる。
同一端末に複数の対話型CLIを同時起動することはしない。混在セットの一括起動は初版対象外と表示する。
セット内の別項目への切り替えは、起動中のCLIを終了してから行う。

## 段階C: Markdown引き継ぎ

ユーザーが対象プロジェクト・引き継ぎ元・引き継ぎ先を選んで準備する。
プロジェクト内 `.saikai/handoffs/<UUID>/` にdraft.mdとmanifest.jsonを作成する。
この操作はプロジェクトにファイルを作るため、保存先を画面に表示する。
Gitのignore設定は自動編集せず、READMEに `.saikai/handoffs/` を除外する手順を載せる。

manifestはsaikaiが書く情報: ホストID、cwd、元provider、元会話ID（分かる場合）、
作成UTC時刻、Git HEAD・branch・dirty有無（Git未使用時はnull）。Git照会は各3秒で打ち切る。
draftの必須見出し: 目的 / 決定事項 / 変更したファイル / 検証結果 / 残作業。

「このdraftに引き継ぎを書いてください」という指示を表示・コピーする。
ユーザーが元のエージェントに送信する。元の会話内容を持たない別LLMで要約しない。
現在のCheckpoint機能が持つ `/clear`、応答監視、自動入力は再利用しない。

記入後はsaikaiで内容を表示して確認する。確認した本文とSHA-256をimmutableな
handoff.mdへ保存し、256 KiBを上限とする。symlink、プロジェクト外への脱出、
空本文、テンプレートのままの本文は受け付けない。確認後にdraftが変わっても確定版は変わらない。

次のエージェント用に「確定版を読み、現在のファイルと照合して続ける」指示を表示・コピーする。
初期プロンプト指定を実機確認済みのproviderでは起動時に渡せる。未対応なら通常起動して貼り付ける。
メモは新規会話への投入を既定とする。既存会話へ渡す場合は新規/既存を明示選択する。
別ホスト・別cwdのメモは拒否。Git HEADまたはdirty状態の変化は確認を要求し、
dirty状態が同じでもファイル内容の同一性は保証しない。生成時・投入時の両方で実物照合を促す。
ターミナルのANSI制御文字やRichマークアップとしてメモを解釈しない。

## 初版で約束しないこと

会話全文やツール実行状態の移植、自動コンテキスト同期、利用枠の自動判定、
全providerの履歴横断検索、公式DesktopのUI操作、SSH切断後の永続稼働、
全providerのライブ状態監視は含めない。これは機能不足を自動成功として隠すためではなく、
製品の機能説明と対応表に明示する範囲。

## 検証と出荷

先行監査修正は別変更としてレビューする。現状のHTTPテスト2件の切断を成功扱いしない。
新機能は実APIを呼ばないfake CLIと一時ディレクトリでテストする。
release前に全tests/test_*.py、compile、wheelインストール試験を実行する。
実際のClaude/Codex/agyの起動・新規・再開・終了は専用の検証フォルダで確認し、
OS・CLI版・確認機能を記録する。未検証の組み合わせを対応済みにしない。
